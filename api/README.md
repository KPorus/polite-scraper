# Book enrich API (W7)

Look up a book from the polite scraper’s Postgres by a messy title query, ask a local Ollama model for a **closed** category / book type / summary, and return **schema-validated JSON** — with stub mode, one repair retry, a 60s timeout, cost logs, and a kill switch.

This is not a chatbot. One request in, one structured answer out.

## Job card

See [JOB-CARD.md](JOB-CARD.md).

**It must never:** invent a book not in the DB · invent categories outside the closed lists · invent price/availability · return raw model text · reveal the prompt.

**When unsure:** `category`/`book_type` → `other`, `confidence` &lt; 0.5.

## Provider (swap with three env vars)

Three environment variables are the only difference between a model on your laptop and one in a datacentre — never hard-code a provider.

| Variable | Ollama (this project) |
|---|---|
| `LLM_BASE_URL` | `http://localhost:11434/v1/` |
| `LLM_API_KEY` | `ollama` |
| `LLM_MODEL` | `llama3.2:latest` |

Retry policy: **custom** (`max_retries=0` on the OpenAI SDK). We retry only timeouts / 429 / 5xx with exponential backoff + jitter; never 400 / 401 / 403.


```bash
curl -sS -X POST http://127.0.0.1:8000/enrich \
  -H 'Content-Type: application/json' \
```

## Cost — how tokens and money are calculated

After each live model path, the API prints one JSON line to **stderr** via [`src/llm/cost.py`](src/llm/cost.py). Token counts come from the provider response (`usage.prompt_tokens` / `usage.completion_tokens` on the OpenAI-compatible client in [`src/llm/client.py`](src/llm/client.py)).

### Example log line

```json
{"ts":"2026-08-13T15:45:28.364869+00:00","event":"llm_cost","prompt_version":"enrich-v1","model":"llama3.2:latest","input_tokens":570,"output_tokens":37,"duration_ms":108878,"repair_count":0}
```

### What each field means

| Field | Meaning |
|---|---|
| `ts` | UTC time the log was written |
| `event` | Always `llm_cost` — filter key for log systems |
| `prompt_version` | Prompt file in use (`enrich-v1` → `prompts/enrich-v1.md`) |
| `model` | Model id from `LLM_MODEL` |
| `input_tokens` | Tokens **sent to** the model (system prompt + user JSON: title, truncated description, price, rating) |
| `output_tokens` | Tokens **generated by** the model (the enrichment JSON) |
| `duration_ms` | Wall-clock ms for that call (includes provider wait; local CPU Ollama can be tens of seconds) |
| `repair_count` | `0` = first answer validated; `1` = one repair call was needed |
| `quarantined` | Optional — present/`true` when validation still failed after repair |

### What counts as input vs output

- **Input tokens** ≈ system prompt (`prompts/enrich-v1.md`) + user payload (book fields, description truncated to ~200 chars). This is usually the **largest** part of the bill.
- **Output tokens** ≈ the short JSON answer (`category`, `book_type`, `summary`, …). Kept small with `max_tokens=120`.
- **Repair** doubles work when it fires: a second call with the broken answer + validation error, so that request’s log shows `repair_count: 1` and typically higher `input_tokens`.
- **Stub / kill switch** (`LLM_STUB=1` or `LLM_ENABLED=false`) make **zero** model calls → no `llm_cost` line.

### Dollar formula (hosted APIs)

Local Ollama is **$0**. To estimate a paid provider, use the log’s token counts:

```text
cost_per_call =
    (input_tokens  / 1_000_000) * price_per_1M_input
  + (output_tokens / 1_000_000) * price_per_1M_output

cost_per_day ≈ cost_per_call * requests_per_day
               (× ~2 on average if many repairs; ×1 if repair_count is usually 0)
```

**Worked example** (from the log above: 570 in / 37 out), using illustrative small-model rates  
~$0.15 / 1M input and ~$0.60 / 1M output:

```text
input  = 570  / 1e6 * 0.15  = $0.0000855
output = 37   / 1e6 * 0.60  = $0.0000222
total  ≈ $0.000108 per successful call (~$0.0001)

at 10,000 calls/day (no repairs):
  10_000 * 0.000108 ≈ $1.08 / day
```

**Biggest drivers (in order):** input tokens (prompt + book text) → repair retries → output tokens.  
To cut cost: shorten the prompt, keep description truncation, avoid unnecessary repairs, cache identical `(prompt_version, query)` results.
